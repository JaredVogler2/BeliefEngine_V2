# Belief Engine

> **Make the village believe it, and reality obeys.** A browser strategy roguelite, played on a living 3D miniature village, where shared belief rewrites the physical laws of a
> small region. You are the Keeper of Stories: you cannot move the river, but you can change what people believe, and enough belief
> becomes law.

Client-only TypeScript (React + Three.js for the 3D village + a Canvas2D fallback map + Web Audio; no art, model, texture or font files to download: everything is generated by code), free to run, no accounts, no analytics, no backend. Saves and settings
stay in your browser. The simulation is a pure, deterministic engine: the same seed and the same actions always give the same world, which is what
makes replays, the bot tournaments and an AI-agent interface possible.

**Status, honestly:** the browser game, the local MCP server and the offline belief composer are built and tested end to end ([`docs/FINAL_ACCEPTANCE.md`](../FINAL_ACCEPTANCE.md) has the table of tracks, commands and proof). **Not deployed anywhere**, so there is no live URL. **No human playtest has been run**: difficulty and fun have been measured on bots, scripts and AI-driven reviews only ([`docs/PLAYTEST_PROTOCOL.md`](../PLAYTEST_PROTOCOL.md) is the script). **Remote MCP is not built** and the **online (language-model) interpreter has never run against a live provider**; both are optional and neither is needed to play. Known limits: [`docs/KNOWN_ISSUES.md`](../KNOWN_ISSUES.md). Build log: [`docs/PROGRESS.md`](PROGRESS.md). Adversarial review: [`docs/FUN_REVIEW.md`](../FUN_REVIEW.md).

**The 3D village.** The default view is a procedural Three.js world (`src/render3d/`, loaded on demand): sculpted terrain, a river and flood that are one surface driven tile for tile by the engine's own water depth, timber-and-plaster houses, a mill, a bell tower, an arched bridge, instanced trees and crops, fourteen animated villagers, weather that follows the forecast, and belief made visible: rings, runes and ripples that appear only for events the engine logged, and ground drawn around a lit beacon that is exactly the ground the engine shields from the flood. The interface floats over it (a slim rail, a tray, a card beside the selection, a side sheet for detail) so the map is at least 75% of a desktop view. The classic Canvas2D map is kept as the fallback and is chosen automatically where WebGL2 is missing or only a software rasteriser is present. **What is and is not verified** is in [`docs/3d-rebuild/STATUS.md`](../3d-rebuild/STATUS.md) and [`docs/3d-rebuild/FINAL_REVIEW.md`](../3d-rebuild/FINAL_REVIEW.md): real browser screenshots, parity tests against real runs and Playwright flows on software WebGL; **never run on a real GPU or a real phone, and no human has played it**.

## Play it

```bash
npm ci
npm run dev                          # http://127.0.0.1:5173
npm run build && npm run preview     # production build on http://127.0.0.1:4173
```

Needs Node >= 22.12. Once loaded the game makes no network requests.

### A three-minute first game
1. **Play**, choose **Flood at Redbank**, **Begin**. Read the briefing, begin day 1.
2. Tap the story card **River fears fire** (or **Bridge stands watched**), tap a villager on the map (try **Ivo Thatcher**), press **Tell Ivo Thatcher** (1 Influence). Undo is free until you end the day.
3. Spend the rest, press **End Day** and read the night digest. Watch the **Laws** tab: support climbs towards the white line.
4. On a good-omen night, pick a landmark (a beacon, the bridge) in **Village > Places** and stage it as proof: people who *see* something change their minds far more than people who only hear.
5. The surge comes on day 7. Check **Tonight** (the forecast) before you end each day, and keep an eye on food.
6. After the debrief, **Retry this seed**, **New seed**, **Try another approach**, or **Share this seed**.

## What is in the game
* **Three hand-made chapters**, each won in more than one way: *Flood at Redbank* (7 days: fire wall, witnessed bridge, bells), *The Harvest That Refused to Grow* (9 days: moonlight work, or a grain caravan that needs a trader's trust) and *The Wolves of Ashwood* (8 days: smoke fires around the pens, or a decoy fire deep in the wood).
* **Expeditions:** a generated village from any seed (river, drought or wolves), with 1-3 run modifiers (e.g. *Stubborn elders*, *Silent bells*, *Restless wolves*). The catalog behind "another village" and the **Daily village** holds only villages that a scripted planner has verified winnable; typed-in seeds still work and are labelled unverified.
* **Share links** carry only the mode, seed and versions (never state or code) and are validated on open.
* **A morning report that says what your story did** (who carried it, who it reached, or why it stalled) and, after a defeat, **what would have changed it**: the run is replayed from each day with other plans and the last day it could still have been saved is named.
* **Rivals and factions** that announce their moves a day ahead and can be answered; villagers who weigh a post on the bridge against their own children; laws that lose credibility when they visibly fail.
* **Inventor mode (optional, unranked):** write a belief of your own in one sentence ("The river turns aside from lit lanterns."). The game reads it into a bounded rule with an offline reader, shows what it would really do, what it needs and what it costs, runs a three-night safety test, and only then lets you pay for it. It still has to be told, spread and powered like any story, and a stronger belief asks more of the village. Sentences the village cannot model (immortality, free food, controlling minds, instructions to the game) are refused with the reason. How it works, what it can and cannot read, and the measured accuracy: [`docs/NL_BELIEFS.md`](../NL_BELIEFS.md).
* **The Atlas of Belief:** laws you have seen take hold, lore, postcards, 20 badges (plus one for Inventor runs), unlocks that add *choices* (pledges, a draft, twists), your stats, and an export/import of the archive. Nothing in it is needed to win a scenario.
* **Save files:** Settings > Download this game / Load a game file.
* **Accessibility and platforms:** keyboard play, screen-reader text for everything on the map, reduced motion, text size, high contrast, 320 px layouts ([`docs/ACCESSIBILITY.md`](../ACCESSIBILITY.md)). Tested in Chromium, Firefox and WebKit builds; no real device has been tested.

Rules (authoritative, matching the code): [`docs/GAME_RULES.md`](../GAME_RULES.md). Procedural generation and modifiers: [`docs/EXPEDITIONS.md`](../EXPEDITIONS.md).

## Let an AI play it (optional)
A local MCP server (stdio, no network, no key) lets Claude Code or another MCP client play real runs with tools, through the same engine as the browser: same costs, same randomness, same hashes. It is optional and the browser needs none of it.
```bash
claude mcp add belief-engine -- npx tsx mcp/server.ts     # from the repository root; verified with Claude Code 2.1.311
npm run mcp:demo                                          # a scripted agent plays a chapter and checks the run against the engine
npm run acceptance:mcp                                    # Journey B: the official MCP SDK client plays a whole game and checks 28 guarantees
```
Other clients: any that can launch a stdio server, with `npx tsx mcp/server.ts` as the command and the repository as the working directory (examples in [`docs/MCP.md`](../MCP.md)). Then ask: *"Start a normal Flood at Redbank game. Inspect the bridgekeeper. Try to win without lighting beacons. Explain each day before acting."* Tools, the coach / delegate / co-op patterns, security, and what is **not** built: [`docs/MCP.md`](../MCP.md). A real Claude Code session played and lost a chapter this way and its run replays identically in the browser engine: [`docs/data/mcp/`](../data/mcp/claude-code-session-redbank-seed11.md).

**Remote MCP: not built, unavailable.** There is no hosted endpoint, no HTTP transport, no authentication and no shared run store. The local server is not a substitute and is not presented as one. What it would need is listed in [`docs/FINAL_ACCEPTANCE.md`](../FINAL_ACCEPTANCE.md).

## Write your own belief (Inventor mode, optional, unranked)
Tick **Inventor mode** in a chapter's briefing, then **Write a belief** and type one sentence: *"The river turns away from lantern flames."* or *"The watched bridge cannot break."*. Previewing is free. An **offline** reader (a fixed vocabulary of seven things the village models, 40 combinations; no model, no network, works with the network off) turns the sentence into a bounded rule, shows what it would really do here, what it needs and what it costs, and runs a three-night safety test; only then can you pay for it. It still has to be told, spread and powered (lit beacons, a vigil, the bell) like any story, and only then does the river or the bridge behave differently. Things the village cannot model (everyone survives forever, free food, controlling minds, instructions to the game) are refused with the reason. Same-sentence replays need no model. Accuracy, limits and the measured numbers (31 of 36 on an untuned final set): [`docs/NL_BELIEFS.md`](../NL_BELIEFS.md).

**Online (language-model) interpreter: optional, off, unverified.** A bounded proxy (`server/interpreter.ts`) and an opt-in checkbox exist, but the site ships with no interpreter URL, nothing is deployed, no provider key was ever supplied, and it has only been tested against a mocked provider. If someone turns it on: the sentence and the names of the village's features leave the device for that server and, through it, a provider; every sentence read that way is a paid request billed to whoever runs the server; the key lives only in the server's environment and never in the browser build. Details and the exact next steps: [`docs/NL_BELIEFS.md`](../NL_BELIEFS.md).

## An example seed and replay
Flood at Redbank, seed 1, the *Fire Wall* route (tell a story, light beacons on the right night): 22 actions over 7 days, victory, score 722, state hash `11ec6d73416e26`. Rebuild it from nothing, with no browser, model or network:
```bash
npm run replay:example                       # prints the result and hashes, exits non-zero unless they match the recorded run
npm run replay:example -- witnessBridge      # the other winning route on the same seed (score 820, gold)
```
In the browser, a seed is typed in the briefing, a run can be shared as a link (`/?mode=expedition&seed=424242&gen=1&rules=1.0.0`, which carries only the mode, seed and versions), and **Settings > Download this game** saves the run including its action log. In an MCP run, `export_replay` returns the action list and the versions it was recorded under; `npm run mcp:verify -- <run file>` replays it and compares.

## Privacy
No cookies, no analytics, no accounts, no third-party requests. `localStorage` holds your autosave, settings and Atlas archive. The shipped page's Content-Security-Policy
(`vercel.json`) allows only same-origin scripts and connections.

## Deploying
Static build in `dist/`. Vercel: framework preset *Vite*, build `npm run build`, output `dist`; `vercel.json` carries the headers and the single-page fallback.
**Nothing has been deployed by this repository's automation, so no live URL is claimed.** Exact steps and the release checklist: [`docs/RELEASE_CHECKLIST.md`](../RELEASE_CHECKLIST.md).
