# Asset and license ledger

The shipped game contains **no third-party art, music, fonts, sound files, textures, shaders or icon packs.** Everything the player
sees or hears is generated by code in this repository, so there is nothing to license beyond the code itself (MIT, `LICENSE`).
This ledger records where each kind of asset comes from so that stays checkable.

> **The 3D world** (`src/render3d/`, the default renderer where the browser can draw it) follows the same rule and has its own ledger: [`docs/3d-rebuild/ASSET_LICENSES.md`](3d-rebuild/ASSET_LICENSES.md). Every texture is painted at load, every mesh is built from primitives, every shader is written here. The rows below describe the classic Canvas2D renderer, which is kept as the fallback.

## Third-party code

Runtime dependencies bundled into the page: `react`, `react-dom` and `three` (all MIT; `three` is only in the lazily loaded 3D world chunk). Everything else in `package.json` is a development tool
(Vite, TypeScript, Vitest, Playwright, ESLint, Prettier, `@axe-core/playwright`, `@modelcontextprotocol/sdk`, `tsx`) and is not shipped
to players. `npm ls --prod` is the authority.

## Rules for adding assets

1. Prefer code over files. A new picture is a function, a new sound is a few oscillators.
2. If a file is ever unavoidable (a font, a sample), add a row here **in the same commit** with its author, source URL, licence text
   and the date it was fetched, and commit the licence file next to it. Do not commit anything whose licence cannot be named.
3. Never copy art, music or text from other games, even "inspired by". The working aesthetic (storybook diorama, illuminated
   manuscript, dark evergreen night, parchment and gold UI) is a direction, not a source.
4. Keep generated files small: screenshots under `docs/screens/` are evidence, not assets, and are produced by
   `scripts/capture-states.ts` from real engine states.
